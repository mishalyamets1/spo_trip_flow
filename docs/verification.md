# Проверка учебной версии TripFlow

Дата: 29 октября 2026 года. Окружение: локальная macOS, Docker Desktop, PostgreSQL 16, Node.js 24.21.0, Next.js 16.4.3. Проверяется реализованная учебная версия контракта 0.2.0.

## Автоматические проверки

- `npm run typecheck`: оба приложения проходят статическую проверку TypeScript.
- `npm run build`: сервер скомпилирован; production-сборка Next.js успешна. Оба Docker-образа также успешно собраны из Dockerfile.
- `npm run format:check`: файлы соответствуют Prettier.
- `node scripts/test.mjs --coverage`: 12 проверок пройдены, 0 ошибок и 0 пропусков при подключении временной БД. Выполняются под trip_app_rw; схема временной базы создаётся владельцем. Проверка имени подключённой базы выполняется до изменения данных.
- После разделения backend на слои покрытие строк services, repositories и validators по измерению Node V8 составляет 99,74 %. Команды подготовки demo-данных исключены. UI, контроллеры, middleware, конфигурация и скрипты в эту цифру не включены.
- `node scripts/database.mjs check`: Q-01–Q-04 возвращают исходные данные отчёта; Q-05–Q-08 успешно ожидают SQLSTATE 23514/23505 с последующим ROLLBACK.
- `npm audit --omit=dev --audit-level=high`: 0 известных уязвимостей на момент проверки. Это проверка списка зависимостей, не полный аудит продукта.

Проверены вход/выход, неправильный пароль, Origin, отсутствие сессии, роли, закрытие чужих карточек, создание/редактирование черновика, точный расчёт суммы, конфликт версии, откат при ошибочной категории, отправка и её повтор, порядок этапов, самосогласование, снимок шаблона, конкурентные решения, итоговое утверждение и отказ с причиной.

## Контролируемый отказ

БД остановлена через `docker compose stop db` с сохранением volume.

Первая проверка выявила дефект классификации ошибки: Docker возвращал ENOTFOUND, ready отвечал 500. Исправлено отнесение ENOTFOUND и других сетевых ошибок к временной недоступности.

Повтор после сборки исправленного API:

- live: HTTP 200, `{status: "ok"}`.
- ready: HTTP 503, сообщение «База данных временно недоступна».
- Лог: event=request_error, code=ENOTFOUND, requestId=3f1b33e2-f62b-4c0b-83c1-c0434ecb25a8; следующий лог запроса показывает HTTP 503.
- После `docker compose up -d db --wait`: ready снова HTTP 200, `{status: "ready"}`. Приложение восстановило соединение без удаления данных.

## Неподтверждённое и оставшееся

- Управление Chrome было отклонено автоматической проверкой разрешений без указания причины; визуальная браузерная проверка и скриншоты не выполнены.
- Два сквозных сценария создания и решения проверены на уровне HTTP/API и БД, но не кликами в браузере.
- Не подтверждены все браузеры NFR-05, ширина 360 px и нагрузочные условия NFR-01.
- Не реализованы публичный HTTPS и административный интерфейс FR-12.
- Исходно отсутствовал Git-репозиторий; реальные теги двух версий и практический откат между ними ещё нужно оформить в командном репозитории. Восстановление БД в новую копию проверено отдельно.
- OpenAPI отформатирован как YAML; полноценная проверка всех контрактов специализированным валидатором ещё не проводилась.
- Материалы этапов II и III находятся в Markdown. Финальные DOCX-отчёты с титульными листами, скриншотами и фактическим вкладом участников ещё не подготовлены.

## Проверка после разделения backend на слои

Код HTTP-операций распределён по controllers, бизнес-операции — по services, SQL — по repositories. Маршруты, middleware, Zod-схемы, типы и криптография также вынесены в отдельные папки. `app.ts` собирает приложение. Транзакции заявок по-прежнему открываются сервисами и используют одно соединение для всех вызовов репозиториев.

После изменений выполнены сборка API, TypeScript-проверка обоих приложений и все 12 проверок на отдельной временной БД. Дополнительно проверены перенесённые обработчики live, auth/me и категорий расходов. Локальный API на порту 4000 ответил ready=200. Рабочие заявки и схема БД при рефакторинге не изменялись.

## Проверка после разделения frontend и добавления роутинга

В Next.js App Router созданы отдельные страницы `/login`, `/requests`, `/requests/new`, `/requests/[id]`, `/requests/[id]/edit` и `/approvals`. Главная `/` перенаправляет на `/requests`. Вместо локального переключателя view используются Next Link и router.push/replace. Фильтры и страница списка читаются из URL, карточки загружаются по параметру id. Форма, карточка, таблица, история, этапы и решения вынесены в компоненты; API-методы, хуки, типы и состояние сессии отделены от страниц.

Production-сборка Next.js и проверка TypeScript обоих приложений прошли. Через временный локальный production-сервер на 127.0.0.1:3100 проверены все шесть маршрутов (200), редирект корня (307) и неизвестный адрес (404). Через тот же Next.js-прокси подтверждены вход, текущая сессия, чтение существующей карточки id=3 и выход (204). Временный сервер после проверки остановлен; пользовательский dev-сервер не останавливался.

`node scripts/test.mjs` завершился с 14 успешными проверками: прежние 12 и две проверки URL возврата после входа. Проверяется сохранение внутренних адресов и фильтров, а также запрет внешних URL, API-маршрутов и циклического перехода на login. Данные рабочих заявок не менялись.

Управление Chrome снова было отклонено автоматической проверкой разрешений без указания причины. Визуальная проверка, клики, переходы Back/Forward и полное взаимодействие с формой в браузере не подтверждены; HTTP, сборка и автопроверки не заменяют эту часть проверки.
