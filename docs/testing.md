# Тестирование на Jest

Тесты на TypeScript запускает Jest 30; ts-jest преобразует TypeScript в ESM. Конфигурация — `apps/api/jest.config.cjs`, проверка типов тестов — `tests/tsconfig.json`. Node.js запускается с `--experimental-vm-modules`, как описано в [документации Jest](https://jestjs.io/docs/ecmascript-modules). Предупреждение VM Modules ожидаемо; формат модулей приложения не менялся.

## Команды

Из корня проекта, после `npm ci`:

```bash
npm test                    # 9 проверок без БД; 27 интеграционных пропускаются
make test                   # все 36 проверок на отдельной временной БД
npm run test:coverage       # полный набор и покрытие, тоже на временной БД
npm run typecheck           # оба приложения и TypeScript тестов
```

Полный набор требует Docker/PostgreSQL, настроенный `.env` и роль приложения (`make setup`). Скрипт `scripts/test.mjs` создаёт `tripflow_test_*`, применяет миграции/SQL-проверки, передаёт её URL в Jest и удаляет только эту БД в finally. Перед первой записью API-тест сверяет имя подключённой базы. Рабочая БД тестами не меняется.

## Организация

- `validation.test.ts` — точные суммы и валидация.
- `auth-crypto.test.ts` — пароли, неверные и повреждённые хэши.
- `web-navigation.test.ts` — выбор рабочего раздела и безопасный адрес возврата.
- `openapi.test.ts` — внутренние ссылки и параметры контракта.
- `api.test.ts` и `helpers/` — настоящий Express/HTTP/PostgreSQL: роли, сессии, заявки, согласование, справочники, удаление сотрудников, отмена, конкуренция и журналирование.

Используются `describe`, `test`, `expect`, `beforeAll`/`afterAll`, `beforeEach` и `jest.spyOn`. Проверки ошибок SQL используют `rejects.toMatchObject`. Запросы отправляются встроенным fetch, БД не подменяется моками. Mock console.log убирает штатные HTTP-логи из вывода; отдельный сценарий перехватывает и проверяет содержимое журнала. Моки восстанавливаются между тестами.

Тесты API образуют последовательный сквозной сценарий: ранние шаги создают данные для следующих. Поэтому запуск — `--runInBand`, без `test.concurrent`/перемешивания. Для интеграции запускать весь `api.test.ts`, а не произвольный поздний шаг по имени. beforeAll открывает сервер/пул, afterAll закрывает их, вложенные группы готовят/очищают свои данные.

## Число тестов и покрытие

Jest показывает **5 наборов, 36 тестов**: 9 без БД и 27 интеграционных. Прежний `node:test` показывал 37, включая внешний тест-контейнер «API и PostgreSQL». В Jest контейнер стал `describe` и в число тестов не входит. Все 36 самостоятельных сценариев сохранены, их названия сверены с прежним набором.

Последний полный запуск: 36 успешно, ошибок/пропусков нет. Строки бизнес-модулей — **97,84%**, ветви — **96,70%**. Область: services/repositories/validators; demo-модули исключены, UI/контроллеры/middleware/crypto/CLI не входят. V8-покрытие рассчитывает Jest, поэтому проценты не сравниваются напрямую с прежним Node test runner.

Отчёты: `coverage/jest/index.html`, `lcov.info`, `coverage-summary.json`. При покрытии строк ниже 70% команда завершается ошибкой. Каталог coverage исключён из Git. GitHub Actions использует `npm run test:coverage`; материалы V этапа сохраняют исторические результаты прежних запусков.
